# WC Stock Log – Ιστορικό Αποθέματος

Πολύ ελαφρύ plugin για WooCommerce που καταγράφει **κάθε αλλαγή αποθέματος** σε προϊόντα και παραλλαγές: **ποιος** την έκανε, **πότε**, **από πού**, με παλιά/νέα ποσότητα και μεταβολή — στο στιλ του «View adjustment history» του Shopify.

## Τι καταγράφει

Κάθε εγγραφή περιλαμβάνει:

| Πεδίο | Περιγραφή |
|---|---|
| Ημερομηνία & ώρα | Αποθηκεύεται σε UTC, εμφανίζεται στη ζώνη ώρας του site |
| Προϊόν / Παραλλαγή | Όνομα + χαρακτηριστικά παραλλαγής (π.χ. «Μέγεθος: 40») + SKU, αποθηκευμένα μόνιμα (μένουν και αν διαγραφεί το προϊόν) |
| Παλιό → Νέο απόθεμα | Και η μεταβολή (+3 / −2) με χρωματιστό badge |
| Συμβάν (πηγή) | Παραγγελία (με link), επαναφορά από ακύρωση, επιστροφή χρημάτων (restock), επεξεργασία προϊόντος, γρήγορη/μαζική επεξεργασία, εισαγωγή CSV, REST API/εξωτερική εφαρμογή (π.χ. ERP, Skroutz sync), cron, WP-CLI, ιστότοπος/ταμείο |
| Χρήστης | Ο συνδεδεμένος χρήστης — και για REST API κλήσεις, ο χρήστης του API key. «Σύστημα / Επισκέπτης» όταν δεν υπάρχει χρήστης |

## Δυνατότητες

- **Σελίδα «WooCommerce → Ιστορικό αποθέματος»** με φίλτρα: αναζήτηση (όνομα/SKU), συμβάν, χρήστης, εύρος ημερομηνιών· ταξινόμηση και σελιδοποίηση.
- **Σύνδεσμος «Προβολή ιστορικού αποθέματος»** μέσα στην καρτέλα Αποθέματος κάθε προϊόντος **και σε κάθε παραλλαγή** (όπως στο Shopify).
- **Εξαγωγή CSV** (με BOM — ανοίγει σωστά τα ελληνικά στο Excel), σεβόμενη τα ενεργά φίλτρα.
- **Αυτόματος καθαρισμός**: ρύθμιση διατήρησης σε ημέρες (προεπιλογή 365, `0` = για πάντα), ημερήσιο cron, διαγραφή σε δόσεις.
- **Συμβατό με HPOS** (custom order tables) — τα links παραγγελιών δουλεύουν και στα δύο σχήματα.

## Γιατί είναι ελαφρύ

- Δικός του **πίνακας βάσης με indexes** (`wp_wsl_stock_log`) — όχι post meta, όχι φούσκωμα του `wp_options` (όλα τα options είναι `autoload=no`).
- **1 INSERT ανά πραγματική αλλαγή** αποθέματος· οι αλλαγές χωρίς διαφορά (no-op) αγνοούνται.
- Στο frontend φορτώνει **μόνο ο logger** (μερικά hooks) — καθόλου CSS/JS.
- Ο κώδικας διαχείρισης φορτώνει **μόνο στο admin**, το CSS **μόνο στη σελίδα του ιστορικού**.
- Καμία εξωτερική κλήση, καμία βιβλιοθήκη.

## Πώς λειτουργεί (τεχνικά)

Καλύπτει και τα **δύο** μονοπάτια αλλαγής αποθέματος του WooCommerce:

1. **`wc_update_product_stock()`** — παραγγελίες, επιστροφές, ακυρώσεις, REST adjust:
   hooks `woocommerce_{product|variation}_before_set_stock` / `_set_stock`.
2. **CRUD save** (`$product->set_stock_quantity()` + `save()`) — επεξεργασία προϊόντος, γρήγορη/μαζική επεξεργασία, εισαγωγή CSV, REST API:
   το `_set_stock` πυροδοτείται από το data store πριν το `apply_changes()`, οπότε η παλιά τιμή διαβάζεται από `get_data()` και η νέα από `get_changes()` — χωρίς κανένα επιπλέον query.

Η απόδοση σε παραγγελία γίνεται με τα status hooks που χρησιμοποιεί το ίδιο το WooCommerce (`woocommerce_payment_complete`, `processing/completed/on-hold` για μείωση, `cancelled/pending` για επαναφορά) **και** με δίχτυ ασφαλείας τα `woocommerce_reduce_order_stock` / `woocommerce_restore_order_stock` / `woocommerce_restock_refunded_item`, που διορθώνουν εκ των υστέρων την πηγή/παραγγελία στις εγγραφές του ίδιου request.

> **Σημείωση:** Αλλαγές που γίνονται με **απευθείας SQL** στη βάση (παρακάμπτοντας τα APIs του WooCommerce) δεν μπορούν να καταγραφούν — αυτό ισχύει για κάθε plugin καταγραφής.

## Hooks για developers

```php
// Αποκλεισμός καταγραφής (π.χ. για συγκεκριμένα προϊόντα)
add_filter( 'wsl_should_log', function ( $should, $product, $old, $new ) {
    return $should;
}, 10, 4 );

// Μετά από κάθε καταγραφή
add_action( 'wsl_logged', function ( $row_id, $row ) {
    // π.χ. ειδοποίηση όταν το απόθεμα πέσει κάτω από όριο
}, 10, 2 );

// Εγγραφές ανά σελίδα στον πίνακα (προεπιλογή 50)
add_filter( 'wsl_per_page', fn () => 100 );
```

## Εγκατάσταση

1. Ανέβασε το φάκελο `wc-stock-log/` στο `wp-content/plugins/` (ή το ZIP από *Πρόσθετα → Προσθήκη νέου → Μεταφόρτωση*).
2. Ενεργοποίησέ το. Ο πίνακας δημιουργείται αυτόματα.
3. *WooCommerce → Ιστορικό αποθέματος*.

Απαιτήσεις: WordPress 6.0+, WooCommerce 7.0+, PHP 7.4+.

## Απεγκατάσταση

Με τη **διαγραφή** του plugin (όχι απλή απενεργοποίηση) σβήνονται ο πίνακας, οι ρυθμίσεις και το cron — δεν αφήνει τίποτα πίσω.
